# plan-phase generator

Прочитай PRd из файла: $ARGUMENTS

Создай план реаализайии и сохрани в файле  'docs/plan-$ARGUMENTS.md' (используй перевод на английский и kebab-case)


## Структура плана:

# Plan: {название фичи}

**PRD:** $ARGUMENTS
**Дата;** {текущая дата}

## Фазы реализации

### Фаза 1: {название}

**Цель:** Что дает эта фаза
**Затрагивает:** backend / frontend / database

**Задачи:**
- [] Задача 1
- [] Задача 2

**Когда готово:** Конкретный критерий

### Фаза 2: {название}
...

## Правила разбивки на фазы:
- Каждая фаза должная давать рабочий результат
- Фазы независимы, можно остановиться на после любой
- Первая фаза как минимальный рабочий путь (Tracer bullet)
- Не боее пяти задач в одной фазе
- backend и frontend одой фичи в разной фазой
- В каждой фазе должны быть запланированы тесты для покрытия функционала фазы.

## Правила
- Читай PRD внимательно, план должен покрывать все критерии готовности
- Не добавляй задачи которых нет в PRD
- Если PRD не полный, задай вопрос перед созданием плана
