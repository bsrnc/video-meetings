# Plan: Загрузка записи встречи

**PRD:** @docs/prd-meeting-recording-upload-and-analysis.md
**Дата:** 2026-08-19

> Фаза транскрибации и анализа (backend pipeline) убрана из этого плана по решению пользователя. План покрывает только загрузку файла записи и отображение статуса загрузки на странице встречи.

## Фазы реализации

### Фаза 1: Backend — приём и хранение записи

**Цель:** API принимает файл записи, валидирует его, сохраняет в object storage и фиксирует ссылку/статус в БД.
**Затрагивает:** backend, database

**Задачи:**

- [x] Миграция Prisma: поля на `Meeting` для ссылки на файл и статуса загрузки (`UPLOADING`/`READY`/`ERROR`), сообщения об ошибке.
- [x] Интеграция S3-совместимого object storage провайдера в `apps/api` (клиент, конфигурация, env).
- [x] Определить лимит размера файла и допустимые video/audio MIME-типы.
- [x] Endpoint загрузки файла записи для встречи: валидация типа/размера, сохранение в storage, запись URL и статуса в БД; невалидный файл отклоняется с понятным сообщением об ошибке.
- [x] E2E-тест (`apps/api`, `test:e2e`) на сценарий фазы: успешная загрузка валидного файла, отказ невалидного типа/размера, доступ endpoint для любого авторизованного пользователя; прогнать и убедиться, что зелёный.

**Когда готово:** Через API-клиент (curl/Postman) можно загрузить валидный файл записи для встречи — файл сохраняется в object storage, `Meeting` обновляется ссылкой на файл; невалидный тип или превышение лимита размера отклоняются с понятным сообщением; e2e-тест фазы зелёный.

### Фаза 2: Frontend — страница встречи и загрузка файла

**Цель:** Пользователь видит область загрузки на странице встречи и может загрузить файл записи, видя статус загрузки.
**Затрагивает:** frontend

**Задачи:**

- [ ] Страница `/meetings/[id]` (с авторизационным гейтом, по аналогии с текущей главной страницей).
- [ ] Блок загрузки файла: выбор video/audio файла, отображение состояния "Загрузка".
- [ ] Вызов backend-endpoint из Фазы 1, обработка успешного ответа — отображение сохранённого состояния записи.
- [ ] Отображение понятной ошибки при отказе backend (неверный тип/превышен размер) с возможностью загрузить файл заново.
- [ ] E2E-тест на сценарий фазы (открыть `/meetings/[id]`, загрузить валидный файл -> состояние обновилось; загрузить невалидный файл -> понятная ошибка, повтор загрузки доступен); прогнать и убедиться, что зелёный.

**Когда готово:** На `/meetings/[id]` без записи видна область загрузки; выбор валидного файла загружает его и отражает сохранённое состояние на странице; выбор невалидного/слишком большого файла показывает понятную ошибку и позволяет повторить загрузку; e2e-тест фазы зелёный.

### Фаза 3: Frontend — статус загрузки на странице встречи

**Цель:** Страница встречи отражает актуальный статус загрузки записи (загрузка / готово / ошибка) без ручного обновления.

**Затрагивает:** frontend

**Задачи:**

- [ ] Опрос/повторный запрос статуса встречи после старта загрузки, отражение состояний загрузка/готово/ошибка без ручного обновления страницы.
- [ ] Индикатор статуса "Загрузка" во время передачи файла.
- [ ] Индикатор статуса "Готово" после успешного сохранения записи.
- [ ] Индикатор статуса "Ошибка" с понятным сообщением при отказе загрузки.
- [ ] E2E-тест на сценарий фазы (статус на странице меняется загрузка -> готово при успехе; загрузка -> ошибка при отказе, без перезагрузки страницы вручную); прогнать и убедиться, что зелёный.

**Когда готово:** После загрузки файла статус на странице встречи меняется загрузка -> готово (или загрузка -> ошибка) без ручной перезагрузки страницы; e2e-тест фазы зелёный.
