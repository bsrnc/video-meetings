# PRD: Загрузка записи встречи и её транскрибация

**Дата**: 2026-08-19
**Статус**: Draft

## Цель

Дать пользователю загрузить запись встречи (видео/аудио) на странице встречи и автоматически получить транскрипцию с анализом — без ручной обработки файла.

## Пользовательские сценарии

- Пользователь открывает страницу встречи без записи -> видит область загрузки файла.
- Пользователь выбирает видео/аудио файл записи -> файл загружается, страница показывает статус "Загрузка".
- Загрузка завершена -> статус меняется на "Обрабатывается", транскрибация запускается автоматически.
- Транскрибация и анализ завершены -> статус "Готово", на странице отображается текст транскрипции и саммари/выводы.
- Обработка или загрузка падает с ошибкой -> пользователь видит понятное сообщение об ошибке и может загрузить файл заново.

## В скоупе

- Новая страница встречи (`/meetings/[id]`) с блоком загрузки записи.
- Загрузка одного видео/аудио файла записи на встречу.
- Сохранение файла в object storage, ссылка на файл — в БД (Prisma).
- Асинхронный запуск транскрибации сразу после успешной загрузки, без ручного действия пользователя.
- Отображение статуса обработки на странице встречи: загрузка / обработка / готово / ошибка.
- Отображение результата на странице встречи: текст транскрипции + анализ (саммари, ключевые выводы).
- Загрузка доступна любому авторизованному пользователю (соответствует текущей модели доступа `Meeting` — без владельца/ролей).

## Не в скопуе

- Владение записью и права по ролям (у `Meeting` сейчас нет owner-поля) — в этой итерации доступ не ограничивается.
- Редактирование или удаление уже загруженного файла/транскрипции.
- Запись видео/аудио прямо в браузере (real-time) — только загрузка готового файла.
- Несколько файлов записи на одну встречу — одна запись на встречу.
- Файлы других типов (документы, изображения, презентации).
- Уведомления о готовности обработки (email/push).

## Технические ограничения

- Лимит размера загружаемого файла — требует определения (записи встреч могут быть большими, десятки–сотни МБ до нескольких ГБ).
- API (`apps/api`) сейчас не интегрирован с object storage — нужен новый провайдер (S3-совместимый) и его конфигурация.
- Транскрибация — тяжёлая асинхронная операция, требует фоновой обработки (очередь/воркер), а не синхронного HTTP-запроса.
- Модель `Meeting` (`prisma/schema.prisma`) не содержит полей для файла записи и статуса обработки — нужна миграция схемы.
- Выбор сервиса/модели для транскрибации и анализа (STT + суммаризация) не определён.

## Критерии готовности

- [ ] Пользователь может загрузить видео/аудио файл записи на странице встречи.
- [ ] Загруженный файл сохраняется в object storage, ссылка на файл сохраняется в БД.
- [ ] Страница встречи отображает актуальный статус обработки файла (загрузка / обработка / готово / ошибка).
- [ ] После завершения загрузки транскрибация запускается автоматически, без действий пользователя.
- [ ] Готовый текст транскрипции отображается на странице встречи.
- [ ] Готовый анализ (саммари и ключевые выводы) отображается на странице встречи.
- [ ] При ошибке загрузки или обработки пользователь видит понятное сообщение об ошибке.
- [ ] Загрузка файла неподдерживаемого типа или превышающего лимит размера отклоняется с понятным сообщением.
- [ ] Любой авторизованный пользователь может загрузить файл в любую встречу.
